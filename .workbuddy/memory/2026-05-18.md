## 2026-05-18 修复 SSE 流式搜索结果显示问题

### 问题
搜索统计数据能正常更新（目标数量、已找到、已验证、运行时间），但表格始终显示空状态占位，搜索结果行没有出现。

### 根因（两个 bug 叠加）

1. **emitDone 发送 String 而非 Object**：`emitDone` 手动拼接 JSON 字符串后用 `.data(payload)` 发送，Spring 会将其作为 String 再次 Jackson 序列化（加上引号转义）。前端 `JSON.parse` 后得到的是字符串而非对象，导致 `applySearchResponse` 中 `data.customers` 为 `undefined`。

2. **applySearchResponse 无条件覆盖 customers**：即使 `lead` 事件在搜索过程中被正确追加到表格，`done` 事件到达后会执行 `searchState.customers = Array.isArray(data.customers) ? data.customers : []`，由于 `data.customers` 不存在，之前累积的所有客户被清空，表格回到空状态。

3. **emitStats 传递 leadLimit 作为 total**：`total` 参数（映射到 `SearchStats.totalCustomers`）在所有调用处都被传成了 `leadLimit`（目标数量），导致"已找到"统计始终显示目标值而非实际找到数。

### 修复内容

**后端 WorkflowSearchService.java**：
- `streamSearchCustomers`：新增 `emittedLeads` 列表，每 emit 一个 lead 时同步记录
- `emitStats`：精简为 4 个参数（去掉无用的 `found` 参数），所有调用处传递 `seenHosts.size()` 作为实际找到数
- `emitDone`：改为构造完整的 `CustomerSearchResponse` 对象发送（含 `customers`、`stats`、`logs`、`summary`），由 Spring 自动 Jackson 序列化
- `fillWithFallbackStreaming`：增加 `emittedLeads` 参数，fallback leads 也同步记录

**前端 customer-search.js**：
- `applySearchResponse`：改为 `if (Array.isArray(data.customers))` 条件覆盖，保留流式搜索过程中已累积的 customers

**缓存**：HTML JS 版本号从 `v=8` 提升到 `v=9`

## 2026-05-18 修复搜索中目标数量显示不正确的问题

### 问题
用户在左侧搜索配置中把"目标客户数"设为 20，但点击搜索后，右侧统计卡片"目标数量"显示的是 12（来自设置默认值），而非用户输入的 20。

### 根因
`handleSearchSubmit` 的执行顺序：
1. `resetSearchViewForPending()` → 调用 `renderStats()` 显示统计卡片
2. `buildSearchPayload()` → 从输入框读取 20 并更新 `searchState.requestedLimit`

由于 `renderStats` 依赖 `searchState.requestedLimit`，而它在 `buildSearchPayload` 之前执行，所以显示的是页面加载时 `hydrateSettings()` 从后端设置里读取的旧值（12）。

### 修复
将 `const payload = buildSearchPayload()` 提前到 `resetSearchViewForPending()` 之前，确保 `searchState.requestedLimit` 先被用户输入值更新，再渲染统计卡片。

**文件**：`src/main/resources/static/customer-search.js`
**缓存**：JS 版本号从 `v=8` 提升到 `v=9`

## 2026-05-18 修复开发信界面导入客户后排版错乱

### 问题
从客户搜索导入客户到开发信界面后，左侧目标客户卡片溢出到右侧开发信编辑区域，长邮箱地址（UUID格式）撑开了卡片宽度，整体布局严重错乱。

### 根因（三个问题叠加）

1. **JS没有切换容器class**：`#recipient-list` 初始是 `class="outreach-empty-recipient"`，导入客户后JS只改了 `innerHTML`，没有移除空状态class。`outreach-empty-recipient` 的 `display: grid; justify-items: center` 样式仍在应用，打乱了卡片的flex布局。

2. **Grid列没有限制最小宽度**：`.outreach-left-column` 没有 `min-width: 0`，CSS Grid默认 `min-width: auto` 会扩展以适应内容。

3. **长邮箱没有换行处理**：`.recipient-meta` 没有 `word-break` 或 `overflow-wrap` 规则，UUID格式的长邮箱地址撑开了卡片。

### 修复

**ai-outreach.js**：
- `renderRecipients()`：空状态时设置 `recipientList.className = "outreach-empty-recipient"`
- `renderRecipients()`：有客户时设置 `recipientList.className = "outreach-recipient-list"`（启用滚动和高度限制）

**styles.css**：
- `.outreach-left-column`：添加 `min-width: 0`
- `.recipient-body`：添加 `min-width: 0`
- `.recipient-meta`：单独提取并添加 `word-break: break-all`

**缓存**：CSS 版本号从 `v=9` 提升到 `v=10`，JS 版本号从 `v=9` 提升到 `v=10`

## 2026-05-18 修复开发信客户卡片仍然溢出的问题

### 问题
用户反馈选择第一个客户（长UUID邮箱）后，左侧客户卡片仍然溢出到右侧编辑区域，排版混乱。

### 根因
`.recipient-body` 使用 `display: grid` 但没有显式定义 `grid-template-columns`。CSS Grid 的隐式轨道默认最小尺寸为 `auto`（即内容的最大宽度），导致即使外层容器有 `width: 100%` 和 `min-width: 0`，网格内部轨道仍被长文本撑开，整个卡片溢出到右侧区域。

### 修复

**styles.css**：
- `.recipient-body`：添加 `grid-template-columns: minmax(0, 1fr)`，显式约束网格列可以缩放到0，强制内容换行
- `.recipient-card`：添加 `overflow: hidden`，作为兜底防止任何残余溢出

**缓存**：CSS 版本号从 `v=10` 提升到 `v=11`
